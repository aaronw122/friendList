## Must-fix
- **BYO onboarding omits the mandatory Spotify "User Management" allowlist step → auth fails for every user.** (§Onboarding 3; §Components 5) A Spotify app in Development Mode requires the *owner* to add each authorizing account (name + Spotify account email) under the dashboard's User Management, up to 25. Since each user owns their own dev app and is its only user, they must add *their own account* there or `ASWebAuthenticationSession` returns "user not registered in the Developer Dashboard." The onboarding lists only create-app → paste client_id → add redirect URI. **Fix:** add an explicit onboarding sub-step "add your own Spotify account under User Management" with the exact dashboard path, and make M2/M3 acceptance include a non-owner-preauthorized account.
- **Menubar login item lost the LaunchAgent's KeepAlive/crash-restart — a crash kills scanning until next login.** (§Architecture; §Components 1 & 2; Tech stack) `SMAppService.mainApp` registers a plain login item: it launches once at login with no `RunAtLoad`/`KeepAlive` relaunch semantics. Collapsing the agent into the app (C1) traded away the one resilience property a LaunchAgent gave. For a "set once, forever" product, a silent crash with no relaunch until logout/login breaks the core promise, and M4's "survives logout/login and reboot" does not cover it. **Fix:** decide the crash-resilience strategy in the plan — either a minimal `SMAppService.agent` watchdog LaunchAgent whose *only* job is to relaunch the app (needs no FDA, so it doesn't reintroduce C1), or an explicit accepted-limitation statement + a self-relaunch-on-crash handler; add a crash-restart line to M4 acceptance.

## Medium
- **Custom-scheme redirect (`friendlist://auth-callback`) may be rejected for new Spotify apps.** (§Components 5; §Onboarding 3) Spotify has been tightening redirect-URI rules toward https/loopback; if custom app schemes are disallowed for newly-created dev apps, the entire "no loopback HTTP server needed" auth design breaks and forces the loopback server the plan explicitly avoided. **Fix:** verify custom-scheme acceptance at M2 on a *freshly created* dev app; if disallowed, switch the documented redirect to `http://127.0.0.1:<port>/callback` with an ephemeral local listener and update onboarding copy.
- **App Nap will throttle/suspend the ~10s poll in a windowless LSUIElement background app.** (§Components 2; §Architecture) A menubar-only app that never shows a window and is rarely frontmost is a prime App Nap target; the poll timer can stretch to minutes, undermining "lands within ~10s." **Fix:** state that the scan loop runs under a `ProcessInfo.processInfo.beginActivity(options: [.background, .idleSystemSleepDisabled? / .userInitiated])` assertion (or equivalent) to opt out of App Nap while scanning; note it in §Components 2.
- **"Requires Premium" appears to be an unnecessary constraint.** (§Onboarding 3; §Components 5; §Risks) The feature set (create/modify private playlist, `me/tracks/contains`, library read) works on **free** Spotify accounts via the Web API; Premium is only needed for playback/streaming control, which this app never does. Gating onboarding on Premium needlessly shrinks the audience. **Fix:** verify at M2 with a free account; if it works, drop the Premium requirement everywhere it's stated.
- **Link regex still misses internationalized paths (unaddressed from R1).** (§Components 4) Still `https?://open\.spotify\.com/track/([A-Za-z0-9]+)`; Spotify mobile shares are now almost always `open.spotify.com/intl-xx/track/ID`, so a real "text yourself a song" test from a phone silently adds nothing. M4 acceptance doesn't force an intl link, so it can pass while broken. **Fix:** allow an optional `/intl-[a-z]{2}` (generic locale) segment before `/track/`.
- **Multi-Mac same Apple ID → duplicate playlist adds.** (§Dedup strategy; §State store) chat.db syncs to every Mac on the Apple ID; two Macs running Friend List share one Spotify account + playlist but keep *independent* per-Mac seen-sets, and `POST /playlists/{id}/tracks` does **not** dedup — so the same link races to two entries before either cache refreshes. **Fix:** define behavior for multiple Macs (e.g., pre-add re-check of the target playlist via `contains`/snapshot, or document single-Mac as a supported constraint in non-goals).

## Low
- **Re-editable client_id lacks a token-invalidation contract.** (§Components 9) Changing client_id in settings invalidates the refresh token issued under the old client_id; the plan lets client_id be re-edited without stating the stored token must be cleared and re-auth triggered. M6 will surface it as an error, but silently. **Fix:** specify that editing client_id clears the Keychain token and reopens Connect-Spotify.
- **`SMAppService` approval state still not handled (unaddressed from R1).** (§Onboarding 4; §Components 1) Registration can land in `.requiresApproval` (user must flip the Login Items toggle); onboarding assumes success, so the app silently won't auto-launch. **Fix:** check `service.status` post-register and guide the user to enable it if pending.
- **Watermark wording still reads as per-message advancement.** (§Scanning loop & watermark discipline; §Architecture line 82) "advance ROWID past every terminally-resolved message" is now paired with "the only thing that holds the watermark is a failed-before-enqueue add," which implies contiguity, but the literal wording still permits advancing past a hole. Since `last_seen` is one scalar, the safe rule must be explicit. **Fix:** state "watermark = highest ROWID such that all lower ROWIDs are terminally resolved; stop at the first unresolved, never advance past a hole."

## Impl-note
- attributedBody: `NSUnarchiver` is deprecated/unavailable in Swift for typedstream blobs (§Components 3) — use `NSAttributedString(data:documentAttributes:)` (streamtyped) or a typedstream parser with the byte-scan `https://…spotify` fallback.
- `chat_message_join` LEFT JOIN can emit multiple rows per message when a message belongs to >1 chat (§Components 3 SQL) → duplicate parse/add passes (dedup backstops the actual add, so wasted work only); add `GROUP BY m.ROWID`/`DISTINCT` or deterministically pick one chat. Caught immediately on group-chat testing.
- Read-only WAL open may return `SQLITE_READONLY_CANTLOCK` when no writer holds the db / `-shm` can't be created (§Components 3); confirm fresh per-poll read-only connections see just-arrived rows (already scheduled M1).
- Advisory `flock` for duplicate-launch guard is fine but largely redundant — LaunchServices already prevents a second instance of the same GUI `.app` by default (§Components 2/8); keep it as belt-and-suspenders in Application Support.
